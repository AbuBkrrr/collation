# My Collation Center — 3-app election observation platform

One backend (Node.js + Express + PostgreSQL + WebSocket) serving three separate apps:

| App | URL | Login |
|---|---|---|
| Command Center | `/command/` | Command passcode (printed once in server console at first start, or set `COMMAND_PASSCODE`) |
| Situation Room | `/room/` | Room ID + passcode — both generated by the Command Center when it creates the room; room must be activated |
| Observer (PWA, Android + web) | `/observer/` | Observer code generated by the observer's own Situation Room (e.g. `OBS-4821-PU012-KN`) |

## One-command start (Docker)
```bash
./start.sh        # asks for your domain/IP once, generates all secrets, then: docker compose up -d --build
```
Starts PostgreSQL, the app, Caddy (automatic HTTPS) and coturn (TURN relay for observers on mobile data), and loads the national location dataset on first boot. The Command passcode is printed at the end. Open `https://<domain>/command/`.
* **Public domain:** point a DNS A record at the server; Caddy gets a Let's Encrypt certificate automatically.
* **Local network:** enter the server's LAN IP; Caddy uses its own local CA (`tls internal`) - install Caddy's root certificate on phones once.
* **Firewall/router:** open TCP 80, 443; TCP+UDP 3478; UDP 49160-49200 (TURN relay).

## How everything connects
Every device makes OUTBOUND connections to the one server (browser/phone -> HTTPS + WSS). Nothing connects device-to-device.
* Command Center and Situation Room PCs: browser -> `https://<domain>/command/` or `/room/`.
* Observers: phone -> `https://<domain>/observer/` (installable app).
* Server: JWT on every call; role + room checked on every query (a room sees only `room_id = its own`, an observer only itself, Command everything). WebSocket carries live push and WebRTC signaling.
* Video/audio: WebRTC, relayed through coturn when the phone is behind mobile-network NAT.

## Run without Docker
```bash
createdb collation && npm install
cp .env.example .env && export $(grep -v '^#' .env | sed 's/ #.*//' | xargs)
npm start
```
HTTPS is still required for phone camera/GPS/mic: put Caddy/nginx in front, or set `HTTPS_KEY`/`HTTPS_CERT`.

## Locations (State -> LGA -> Ward -> PU)
Loaded automatically from `seed/locations.json` on first boot. Command Center -> Locations can reload it, fetch JSON from a URL, or import CSV/JSON (nested or flat).

## Optional config
* `PARTIES` – full 2027 registered list.
* Command Center → Locations: import `state,lga,ward,pu,reg` CSV (the INEC PU register) so rooms pick LGA/ward/PU from cascading lists.
* `STT_URL` – local speech-to-text service (accepts audio POST, returns `{"text":"..."}`) used when the phone's built-in voice typing is unavailable.

## Data
Text data lives in PostgreSQL on the server PC; video clips in `DATA_DIR/clips`. Both apps can export CSV/JSON and download clips; every export is audit-logged.

## What changed in this version
* **LiveKit SFU + simulcast:** observers publish 3 quality layers; viewers get the best layer their network allows (falls back to direct WebRTC if LiveKit is not configured). Talkback = viewer microphone into the same LiveKit room. Restream to YouTube/Facebook/Twitch: feed panel -> "Restream" (needs the `egress` service, enabled by `COMPOSE_PROFILES=restream`).
* **App Settings (Command Center):** app name (login screens, top bar, tab title, observer app), Command passcode change, feed-sharing webhooks, optional cloud sync.
* **Windows test:** run `setup-windows.ps1` as Administrator.
* **Android APK:** `cd mobile && npm i @capacitor/core @capacitor/cli @capacitor/android && npx cap add android`, set your domain in `capacitor.config.json`, add CAMERA, RECORD_AUDIO and ACCESS_FINE_LOCATION to `AndroidManifest.xml`, then `npx cap open android` and build in Android Studio.
* Open ports for LiveKit: TCP 7881 and UDP 7882 (plus 80/443).

## Radio gateway (SDR -> Situation Room)
A phone cannot receive P25/TETRA/DMR. A fixed "listening post" at the Situation Room (or any site with good radio coverage) does:
1. Room app -> Radio panel -> **Gateway key** (shown once; each room has its own).
2. On the listening PC: RTL-SDR dongle(s) + antenna + a decoder (GopherTrunk, or the older trunk-recorder / SDRTrunk) saving each call as a .wav/.mp3 in a folder.
3. Run the forwarder next to it: `SERVER=https://your-domain GATEWAY_KEY=GW.SR-XX-ABC.xxxx WATCH_DIR=/path/to/recordings node radio-gateway/forward.js`
   Each finished call appears in the room's Radio panel with frequency, talkgroup, unit and a play button. Other tools can POST JSON to `/api/radio/ingest` (header `X-Gateway-Key`) for text events.
4. Observer-side frequency reports (for a future native Android app with an OTG SDR): `POST /api/observer/spectrum {"hits":[{"freq":460.125,"power":-31}]}`.
Encrypted channels cannot be decoded. Check that monitoring your target channels is authorised.

## Offline speech (Vosk, on the phone)
The Docker build downloads the small English Vosk model (~40 MB) to `public/models/`. The observer app uses the phone's built-in voice typing when online and switches to on-device Vosk (WebAssembly) when offline or unsupported; the model is cached after first use (pre-fetched on Wi-Fi). Spoken numbers ("two hundred and fifty one") are converted to digits. Without Docker run `sh scripts/get-vosk-model.sh`.

## Several Command operators
Command Center -> App Settings -> Command operators: each person logs in with their own name and passcode (first login: `admin`). Every action is audit-logged under that name.

## Several independent Command Centers (multi-tenant)
Platform administrator (the first `admin`) -> Command Centers tab -> create a Command Center with its first operator. Each Command Center has its own rooms, observers, operators, contacts, messages/broadcasts, clips, exports, audit log, app name, webhooks and cloud sync, and cannot see or touch any other Command Center (enforced on every server query and on live video/signalling). Only the platform administrator can create/disable Command Centers (disabling suspends its rooms), import the national location list and set the platform name shown on login screens. Existing data became "Main Command Center".

## Radio for plain analog voice ("over, over")
No digital decoder is needed. Use `radio-gateway/analog-record.sh <freq MHz> <dir>` (one dongle per channel; receive-only) or trunk-recorder's analog conventional mode (many channels within ~2 MHz on one dongle), then run `radio-gateway/forward.js` on the same folder. GopherTrunk is only needed for digital trunked systems.
